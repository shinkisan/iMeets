# 睡眠中暂停：仅补实际经过的睡眠段

2026-11-13。当前状态：**build 10026 接入为默认行为，无设置开关。仅对代码指纹及睡眠状态均可确认的 Sweets 普通角色启用。**

## 用户确认的规则

只有在宠物实际处于睡眠状态时开启暂停，恢复时才考虑睡眠补算。
只补实际暂停经过的时间，最多到这一次自然醒来；醒来之后仍未恢复的白天不补算。
补算完成后，再按现有行为对齐手机RTC和SoC日内时钟。

例如，假设本次睡眠的自然醒来点是07:00，23:00时按暂停：

| 实际恢复时间 | 应补算的段 | 其余处理 |
| --- | --- | --- |
| 23:10 | 23:00→23:10，共10分钟 | 对齐23:10，仍在睡眠 |
| 次日01:00 | 23:00→01:00，共2小时 | 对齐01:00 |
| 次日12:00 | 23:00→07:00，共8小时 | 跳过07:00→12:00，对齐12:00 |
| 隔几天12:00 | 只补第一次23:00→07:00 | 不把后续几个夜晚都算进去 |

在作息不变的简单情况中：

```text
应补时间 = min(max(恢复Unix时间 - 暂停Unix时间, 0), 本次剩余睡眠时长)
```

不能把后者当作所有角色统一固定的8小时，也不能恢复时按当前日期重新挑一个次日醒来点。
如果回放期间成长或事件改变了睡眠，必须在实际状态变化时重新判断，不能盲目跑完旧的预计时长。

## 为什么可行：真实固件的夜间回放

目标为当前已验证的 JP Sweets v062：

- SHA-256：`1b0972205bc104183e2406510f264d7ed4193bb5dc08c4811447ab986bbd2305`
- `tg18::code_hash`：`0x28ad63c34fa9e369`

使用 Capstone 5.0.6 和现有 tg18-core；不是 REA Evidence。
只读取原始ROM及私有存档，实验运行独立副本，不操作两台手机或正在展示的17 Pro模拟器。

自然流程实验：载入真实成人存档，人工把RTC/TOD定位到21:00；**没有修改成长、满腹、心情、失误等养育字段**。
先正常执行10秒观察入睡，再关闭强制常亮（`never_sleep = false`），通过正常 `Session::step` 回放到翌日07:02。
没有给成长分钟直接加值，也没有为这一分支手工调用分钟处理函数。

观察结果：

- 21:00→07:00，成长分钟G从4513增加到5113，即**600分钟**。
- 本样本满腹0、心情15，睡眠段保持不变，失误85和疾病累计2也未增加。满腹初始已为0，不能仅凭它证明有饱腹值时也不下降；分钟函数作息状态3提前返回的静态路径另支持夜间需求保护。
- 回放中CPU会深度断电；固件通过每分钟的RTC闹钟冷启动处理时间，并继续休眠。
- 07:00，SRAM `F800D7D4` 的状态从3变0。此时CPU仍可能断电、`alarm_wake = true`；所以CPU/LCD关着不等于宠物仍在睡觉。
- 继续到07:02并按B显示后，G为5115，需求下降计时已消耗清醒分钟。**这最后两分钟是实验观察晨起用的，不是建议给暂停用户额外补的白天时间。**

私有证据：`../tama-private/sleep-pause-research/night.log`，以及同目录探针源码和输出。
只验证了这一个成人样本的一晚，不代表所有角色、婴儿小睡、成长事件或全部异常状态都已经覆盖。样本的闹钟在每分钟第5秒触发，07:00:05才观察到睡眠状态退出；正式补算必须处理首次醒来的几秒粒度，不能用大的step越过边界。

## 作息识别的已知路径与限制

固件函数 `0x20157454` 根据阶段和当前内部时分返回作息状态：

- stage2/3经 `201288F2(1,0)` 选取角色记录；adult经 `(0,0)`。
- 所选记录 `+0x17` 为醒来小时、`+0x18` 为睡觉小时；当前小时在清醒区间外返回3。
- 本样本作息为07:00醒、20:00睡；不能外推到所有角色。
- stage1有G在30..34时的特殊短睡分支，不能套成人跨夜公式。
- 成人记录可能来自flash资源表，受角色/资源选择标志影响；不能直接用固定ROM表中的当前角色行号当作唯一作息来源。
- `F800D7D4 == 3` 与该作息状态共同构成较有用的实际睡眠候选条件，但正式实现仍需核对状态设置路径、冷启动SRAM重建及角色覆盖。

仅凭 `Session::asleep()` 不足以启用本功能：它实际返回 `powered_off || alarm_wake`，表达的是CPU/显示唤醒状态。

## 实现约束

1. 在暂停当时记录可信的宠物睡眠状态、虚拟RTC和此次睡眠边界；兼容性按代码指纹判断。
2. 保留旧的虚拟RTC先回放，不能先调用当前的 `resume_clock_to`，否则已经越过了要补的夜间。
3. 用原固件正常执行睡眠段，允许闹钟、日历、成长和晨起处理自然发生；不直接修改成长、年龄或需求字段。
4. 使用分片预算和进度显示，避免把数小时回放塞入一次UI操作；补算期间不弹历史呼叫/便意通知。
5. 在实际首次醒来或到达实际暂停时长时停止，之后才对齐手机RTC/TOD。不能让一般离线补算把剩余白天再次补进去。
6. 将剩余补算进度与存档一起保存；杀App重开、重复点击恢复、再次暂停不能造成重复加算。
7. 未知ROM、无法可靠识别睡眠、婴儿短睡等未覆盖情况，保留原来的“不补暂停间隔”行为。
8. 回归覆盖短暂停、跨午夜、超过醒来点、跨多天、多次暂停、重开App、角色成长改变作息，以及恢复后需求和失误没有被多算。

现有代码的暂停、RTC和离线补算证据见 [暂停时钟审计](age-pause-clock-audit.md)。

## 实现与回归

- `sleep.rs` 只读识别实际睡眠及当前夜晚边界。儿童/少年读取已验证原生表；成人解析正常资源bank相对指针并比对已验证角色元数据。婴儿短睡、备用/下载资源、异常照顾或不一致时钟保留普通暂停行为。
- `CareTimeline.sleep_pause` 保存暂停时的睡眠凭据；恢复时以真实暂停间隔和剩余睡眠的较小值创建固定终点的 `sleep_replay`。旧版暂停元数据若保留了开始时间且当前冻结快照仍可验证，也可使用本功能。
- `Session::pump` 分片推进原固件，补算期间关闭强制常亮并抑制历史声音/呼叫；RTC在完成前保持夜间虚拟时间。名义起床边界是硬上限，若确认提前醒来则立即停止。参数短暂重建最多宽限5模拟秒，持续无法验证时停止。
- 固定终点在首次回放前写入元数据；进度以保存快照的RTC恢复，避免独立写文件的顺序造成重复加算。完成后先保存带completed凭据的夜间快照，再对齐RTC并保存正常状态；completed凭据残留也不能重复回放。
- 暂停补算途中再次暂停时保留原终点，不追加第二份夜间预算；反复点击恢复不改变终点。
- 96项Rust测试通过，带真实ROM和夜间存档：10分钟短暂停、跨多天仅补一次睡眠、完成后RTC跳时不补白天、实际醒来停止、保存重开/重复恢复/补算中再暂停、旧格式暂停存档兼容、未知ROM及清醒暂停不补算、只读睡眠识别及作息边界。
- 夜间样本在分钟闹钟冷启动时有既有 `00300A00`/`00000001` unmapped提示。独立对照60秒、10秒、0.5秒及混合切片，180秒均6条，成长、需求、失误、疾病和flash写次数一致；并非本功能分片新增。尚未定位该核心提示的根因。

后续限制：完整自然养育的实测仍以成人样本为主；儿童/少年边界有只读表和合成测试，尚未逐角色运行整夜。保守拒绝识别结果时不会改写成长或补一段推测的睡眠。
